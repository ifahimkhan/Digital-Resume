ShieldCheck Security Companion

Quick Summary (TL;DR)

ShieldCheck is built with a privacy-first, offline-local philosophy. The app helps you audit security risks on your device without harvesting your information. Here is the core of our commitment to you:

100% Offline Scanning

All app audits, device checks, and network port analysis happen strictly on your device.

Secure Local Storage

Data is saved in a 256-bit SQLCipher encrypted database, locked by hardware Keystore keys.

Verify & Open Source

Our source code is fully open and auditable under the MIT license, verifying these privacy claims.

Information We Process

Unlike typical security tools, ShieldCheck does not upload, sell, or monitor your personal data. The information we process never leaves your phone:

  • Installed Application Information: We read the names, package identifiers, and permission requirements of your installed apps to evaluate permission risks. This assessment is calculated locally in our proprietary risk scoring system.
  • Usage Statistics: If explicitly granted, we check app usage details locally to discover if high-risk permissions are actively being utilized by background apps.
  • Diagnostic & Device Status: We inspect system flags such as root status, storage encryption, screen lock status, and developer parameters (USB debugging) to compute your aggregate device security score.
  • Local Network Infrastructure: We check active WiFi attributes (e.g. security configuration, local IP address, active VPN connection) and inspect local ports on common channels to locate active network risks.

Permissions ShieldCheck Requires

To conduct security diagnostics, Android requires ShieldCheck to declare specific permissions. Below is an interactive map detailing every high-level permission requested, its risk score weight within the app, and why we request it:

System API Name: android.permission.QUERY_ALL_PACKAGES

Purpose: Required for the "App Permission Auditor" feature. Without this permission, Android prevents ShieldCheck from listing third-party applications, which is essential to assess which background applications hold critical permissions like access to your Camera, Microphone, or Location.

Security Guarantee: This information is compiled into a local UI checklist, mapped against risk weights, and stored inside the local database. No list of applications is ever transferred off your device.

System API Name: android.permission.PACKAGE_USAGE_STATS

Purpose: Optional permission granted manually through system settings. Used to inspect when and how frequently other apps run, allowing ShieldCheck to notice if an app with high-risk permissions is executing suspicious background routines.

Security Guarantee: Data queried is purely diagnostic. It is read dynamically and is not written to permanent local storage, nor is it transmitted to any external API.

System API Name: android.permission.ACCESS_NETWORK_STATE, android.permission.ACCESS_WIFI_STATE

Purpose: Used by the "Network Security Scanner" to retrieve network diagnostics. We check the active SSID, protocol type (WEP, WPA2, WPA3), check if an active VPN tunnel is routing system packets, and obtain your local network subnet range.

Security Guarantee: Network checks are strictly passive and local. Information is only used to warn you if your WiFi configuration lacks modern security safeguards.

System API Name: android.permission.INTERNET

Purpose: Although ShieldCheck does not connect to external servers, Android requires this permission to run local socket operations. This enables our scanner to query common local port interfaces on the loopback (`127.0.0.1`) and local IP ranges to warn you about vulnerable open ports.

Security Guarantee: This socket communication is purely inward-facing. No outgoing telemetry packets are sent over the WAN.

Data Security & Encryption

We treat your local diagnostic logs with security matching corporate data protection protocols. ShieldCheck employs three layers of cryptographic isolation to safeguard scanning history:

SQLCipher DB Encryption

All historical audit logs and scan parameters are saved in a local SQLite Room database, encrypted at-rest using 256-bit AES database encryption through SQLCipher. This prevents rogue malware or root explorer applications from reading ShieldCheck data.

Android Keystore Integration

The master key used to seal the database is generated and held securely within the device's hardware-backed Keystore system. The key cannot be extracted by the software OS and remains isolated inside a secure enclave (TEE/StrongBox).

Third Parties and Data Sharing

Since we do not run application servers, cloud databases, or track crash metrics remotely, we do not collect, share, lease, or distribute your information to any third parties.

  • No Tracking Analytics: We do not integrate telemetry SDKs like Google Analytics, Firebase Analytics, Mixpanel, or Flurry.
  • No Advertising SDKs: There are no advertising scripts, software trackers, or cookies built into our binary.
  • Zero Third-Party APIs: ShieldCheck does not query online APIs for data parsing or categorization. All security rules are bundled statically inside the app.

Data Retention

Your diagnostic scans are stored locally on your device indefinitely to render your historical privacy trends.

This data will remain on your device unless:

  • You select the "Clear History" option in ShieldCheck Settings.
  • You uninstall ShieldCheck from your device. Under standard Android processes, the local Keystore keys and the encrypted SQLite database are permanently wiped by the Android OS upon app deletion.

Your Rights and Choices

Because ShieldCheck processes everything on your device, you maintain full control over your diagnostic parameters:

  • Revoke Permissions: You can modify or completely disable access to Usage Statistics or Network information by navigating to Settings > Apps > ShieldCheck > Permissions on your Android device.
  • Local Wipes: You can clear the entire scan database at any point from within ShieldCheck's in-app Settings panel or via the system's "Clear Data" option in Settings.
